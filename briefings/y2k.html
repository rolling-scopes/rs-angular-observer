Risks / uncertainty zones:

  • Repository Pattern implementation: he describes it clearly in the diary, but Angular's DI-based approach to this pattern is subtle. Worth probing whether he understands why it works through the DI container, not just that it works.
  • <ng-container> / structural directives: the mentor demonstrated this in the meeting (2026-06-03). ngInit found it "very cool" but noted the app was "still small." Not yet self-built — this is textbook surface, not production muscle.
  • Firebase Auth / Firestore: just added (PR #93, #94, still open PR #99). Risk: if it doesn't compile cleanly, it's shallow. Worth checking if he can explain the Firebase DI token setup without looking at the docs.
  • No AI tool usage mentioned explicitly in diaries. No signs of heavy library scaffolding beyond Angular Material and Firebase — the stack choices appear deliberate rather than cargo-culted. That said, absence of AI mention is not proof of absence.
  • Solo context: Without teammates, there is no PR review trail on his feature work. He is both author and merger. Self-review is inherently weaker than peer review. The interview is the first real external check.

Probe questions for the interview

Primary probe — Repository Pattern (what he built, can he re-explain from scratch):

"Walk me through how you switched between mock data and real Jamendo data. Specifically: where does Angular's DI container enter this — how does your service know which implementation to use, and what would you change if you added a third source?"

This is his own design choice, documented in the diary. If he can explain the DI registration side (not just the interface), it's real. If he freezes on "where does Angular inject it," that's the gap.

Secondary probe — Lazy loading + guard wiring:

"You said Landing is eager, others are lazy. Show me in the route config where that distinction lives. Now: what happens if a user tries to navigate to /user without being authenticated — walk me through the exact sequence of calls."

He built this (PR #60 + diary). If he can trace canActivate → AuthGuard → AuthService → redirect path, it's solid. If he knows only "it works," that's surface.

Tertiary probe — CI reasoning:

"In your CI workflow you run ESLint and Prettier in parallel. What would break if you made them sequential instead — and is there any case where sequential would be better?"

He explicitly reasoned about this in the diary. A good student will restate the reasoning. A surface student will say "parallel is faster."

Conclusion for the mentor

Situation: You are interviewing a solo student. There are no passengers, no balance issue, and no team dynamic to probe. The entire output is one person's work. The question is not "who carried the team" but "how deep does this one person go."

Strengths (grounded): ngInit shipped a coherent feature progression at high pace — 44 merged PRs in 3.5 weeks. He did not just scaffold; he reasoned through routing architecture, implemented Repository Pattern as a problem-solving move, set up CI with explicit concurrency reasoning, and documented his learning process with enough specificity to be cross-checkable. His diaries read like engineering logs, not summaries generated after the fact. He found a bug in his own Prettier setup (WebStorm SCSS watcher interference), diagnosed it, and fixed it — small signal but right type.

Watch points:

  1. Solo = no peer review = first external code check is this interview. Probe for understanding of "why it works," not just "it works."
  2. Firebase is freshly added and the sign-in PR is still open. Avoid letting him demo the parts he hasn't finished yet — redirect to the completed routing/player/repository work.
  3. Angular Material: he uses it heavily (carousel, cards, inputs). Check he understands Material tokens / ::ng-deep trade-offs, not just "I used the component."
  4. Sprint depth vs breadth: he covered a lot of ground fast. The risk is that some features were wired up without internalization (especially <ng-container> / structural directives he learned from the mentor demo — not self-built yet).

Recommended interview angle: Pick two things he explicitly built himself (Repository Pattern + routing/guards), ask him to explain them as if teaching. Then pick one recent thing (Firebase DI setup or the CI workflow). The goal is to find the exact depth boundary — where does "I built it" end and "I followed the pattern" begin. For a solo student, that boundary tells you everything.

Overall readiness: Above average for a solo mid-course student. Pace and methodical documentation suggest genuine engagement. The interview should be a technical calibration, not a remediation conversation.

Заключение для ментора

Ситуация: Вы интервьюируете соло-студента. Пассажиров нет, нет вопроса баланса и командной динамики. Весь выхлоп — работа одного человека. Вопрос не «кто тянул команду», а «насколько глубоко заходит этот один человек».

Сильные стороны (подкреплённые): ngInit выкатил связную прогрессию фич в высоком темпе — 44 смёрженных PR за 3,5 недели. Он не просто скаффолдил: рассуждал об архитектуре роутинга, реализовал Repository Pattern как проблемно-ориентированный ход, настроил CI с явным обоснованием параллельности и задокументировал процесс обучения с достаточной конкретикой, поддающейся перекрёстной проверке. Его дневники читаются как инженерные логи, а не резюме, написанные постфактум. Он нашёл баг в своей конфигурации Prettier (интерференция SCSS-вотчера WebStorm), диагностировал его и починил — небольшой сигнал, но правильного типа.

На что обращать внимание:

  1. Соло = без peer review = первая внешняя проверка кода — это данное интервью. Проверяйте понимание «почему работает», а не просто «работает».
  2. Firebase только что добавлен, PR с формой входа ещё открыт. Не давайте ему демонстрировать незаконченные части — перенаправляйте на готовый роутинг/плеер/репозиторий.
  3. Angular Material: он использует его активно (карусель, карточки, инпуты). Проверьте, понимает ли он компромиссы Material-токенов / ::ng-deep, а не просто «я использовал компонент».
  4. Глубина vs ширина по спринтам: он прошёл много маршрутов быстро. Риск — что часть фич была подключена без интернализации (особенно <ng-container> / структурные директивы, которые он узнал из демо ментора — ещё не построено самостоятельно).

Рекомендуемый угол интервью: Выберите две вещи, которые он явно построил сам (Repository Pattern + роутинг/гарды), попросите объяснить их, как будто обучает. Затем возьмите одну свежую вещь (настройка DI Firebase или CI-воркфлоу). Цель — найти точную границу глубины: где заканчивается «я это построил» и начинается «я следовал паттерну». Для соло-студента эта граница говорит всё.

Общая готовность: Выше среднего для соло-студента в середине курса. Темп и методичная документация свидетельствуют о подлинной вовлечённости. Интервью должно быть технической калибровкой, а не разговором-исправлением.
