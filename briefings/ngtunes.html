Mentor briefing — ngTunes

Cross-interview briefing · RS Angular 2026 Q2

Source: repo angular2026q2/musicflow (commits, PRs, merged PR titles) + sprint diaries on main branch. Snapshot 2026-06-15. Goal: give the mentor 2 minutes of context before the defence — who built what, who understands it, what to probe.

One-liner (internal): Three genuinely active students; solidados is the technical backbone (backend + auth + infra), cherkasovaa is a reflective lead growing fast in component architecture, shvetsby is a steady UI assembler leaning heavily on PrimeNG — lightest commit count by almost 3x, minimal diary depth; no passengers, but the gap is real.

Project

MusicFlow — a music streaming service SPA. Users can search tracks/artists, play audio via a global player, build playlists, and upload their own files. The music catalog is backed by Jamendo API v3 (500 K+ free-license tracks); user data lives on a custom NestJS backend deployed on Railway, using Supabase for auth (JWT) and PostgreSQL. Frontend is Angular 21 + PrimeNG.

  • Repo: https://github.com/angular2026q2/musicflow
  • Live demo: https://angular2026q2.github.io/musicflow/
  • Created: 2026-05-09 · Last pushed: 2026-06-15 · Open issues: 41
  • Stack: Angular 21, PrimeNG, NestJS 11, Supabase, Railway (free tier), GitHub Actions CI/CD, Husky + lint-staged + commitlint, Stylelint + ESLint + Prettier, Lucide icons.

Notable: the team built a real backend (not a mock), deployed it on Railway free tier, hit real-world constraints (Railway monthly hour limit), and solved them via env-gated config. This is more end-to-end ambition than most teams on this course.
