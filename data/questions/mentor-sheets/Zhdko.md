# Zhdko — Дрим Тим

**Tech:** Angular, ESLint, RxJS, SCSS, TypeScript

## Context (read before the call)
- Взял на себя роль tech/design lead по UI — самостоятельно построил весь UI Kit команды с нуля (кнопка, инпут, чекбокс, тостер) и разработал дизайн приложения в Figma, работая с Angular впервые.
- Суммарно вложил 40–60 часов только в компоненты UI Kit: кнопка — 12ч, инпут с ControlValueAccessor — 14ч, тостер — 16ч с доработками.
- Самостоятельно вывел связь между Angular signals и паттерном Observer — не из документации, а через анализ того, как должно работать изнутри.
- Исследовал trade-offs в реальном коде: BehaviorSubject vs signals для тостера, function overloading vs type guards для API, ControlValueAccessor vs nativeElement для форм.
- Осознанно пошёл на технический компромисс (временное решение в API тостера) из-за усталости после ночной работы — и сам это зафиксировал как долг.
- Анализировал конкурентов (LeetCode, Codewars) при проектировании дашборда — мыслит на уровне продукта, не только реализации.
- Сознательно отказался от over-engineering: при проблеме с анимацией ошибки в инпуте решил не вводить дополнительный буферный сигнал ради микро-эффекта.

## Trade-offs
- В Angular есть несколько подходов к работе с формами — какой выбрали вы и почему? Что теряешь, если выбрать другой путь?
